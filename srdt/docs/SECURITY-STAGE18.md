# Безопасность и эксплуатационные ограничения — Stage 18

**Лабораторный прототип, не публичный VPN/proxy.** Успешные сборка и регрессии не являются
аудитом криптографии, доказательством корректности или готовностью к эксплуатации.
Исторический полный список исправлений: [SECURITY-STAGE17.md](SECURITY-STAGE17.md),
[AUDIT-STAGE15.md](AUDIT-STAGE15.md). Точные изменения: [STAGE18.md](STAGE18.md).

## Что обеспечивается кодом и проверяется тестами

Аутентификация предшествует изменению состояния пакета; неверный пакет не сбрасывает
сессию и не продвигает replay window. Повтор HELLO активной сессии не создаёт заново
старые ключи со сброшенным nonce. История использованных HELLO не вытесняется в рамках
identity, а при заполнении лимита новые сессии отклоняются.

Receiver проверяет конфликтующий фрагмент до изменения сборки. ACK неотправленных байтов
не принимается; дубли не освобождают окно дважды. Идентификаторы сообщений монотонные,
не переиспользуются, имеют ограниченное допустимое отставание.

DATA не создаёт приёмный резерв самостоятельно. Резервирование окон и владение буферами
ограничивают удерживаемые данные; дополнительно ограничены число сообщений и дескрипторов.
Pacer Stage 18 ограничивает попытки передачи DATA, в том числе повторы. Дубликат ACK не
увеличивает congestion window. Увеличение/уменьшение окна не отзывает резерв получателя.

## Оставшиеся блокирующие вопросы

1. Криптографический протокол X25519+общий лабораторный PSK/AES-256-GCM не заменён проверенным
   handshake. Нет индивидуальной авторизации/отзыва, безопасного долговременного
   provisioning/rotation, серверной forward secrecy внутри запуска. PSK в CLI виден в
   history/process list: реальные ключи здесь не использовать.
2. Нельзя восстанавливать прежний private key с пустым replay-реестром. Серверный реестр
   по умолчанию ограничен 65536 ID, identity — 1000000. Ротация эпох нужна для долгой работы;
   ручная очистка реестра при том же ключе небезопасна.
3. Контроллер Stage 18 считает логические байты, не отдельные физические копии. Нет ECN,
   packet-level ACK/loss detection, полной TCP-fairness, контроллера совокупного канала всех
   клиентов. И ACK, и credit traffic исключены из DATA-pacer; это не общий rate limiter.
   Атакующий, удаляющий пакеты, может заставить контроллер уменьшать throughput.
4. Нет полного anti-amplification/path-validation, индивидуального лимита по авторизации
   и испытаний flood/DDoS. Много медленных/авторизованных клиентов может занять глобальные
   резервы до timeout. Memory-budget не является лимитом всех CPU/сетевых затрат.
5. BufferBudget считает payload/bitmap/reserved range metadata, не RSS. Runtime, allocator,
   maps, fixed controller state, crypto и kernel socket buffers требуют дополнительной памяти.
   GOMEMLIMIT — мягкий лимит Go runtime, не cgroup/RSS cap.
6. Exactly-once относится к живой ограниченной сессии, не к durable application commit.
   Нет восстановления после crash, NAT migration и надёжного финального закрытия. Потеря
   последних ACK может оставить резерв сервера до timeout после завершения клиентского echo.
7. В окружении Go 1.23.2, вне поддерживаемых веток. Попытка доступа к go.dev для обновления
   здесь завершилась ошибкой DNS. Новый compiler/govulncheck не запускались. Нет внешних
   модулей, но стандартная библиотека и runtime тоже могут иметь уязвимости. Нужны актуальная
   поддерживаемая Go, повторная сборка и vulnerability scan.
8. Нет гарантий устойчивости к DPI/ТСПУ. HELLO 81 байт, ACK 62 байта и старые controls 58
   байт сохраняют фиксированные размеры. Новые WINDOW controls имеют padding; вариативные
   повторы DATA не позволяют обойти блокировку всех носителей/служебных сообщений.
9. Нет реального запуска Windows, узла 2 ГБ со слабым CPU и Xray, WAN/ТСПУ или многодневных
   испытаний. CLI и библиотечный протокол не следует публиковать с настоящими клиентами.

Session/Queue/Receiver имеют единственного владельца и не являются concurrent-safe.
Borrowed scratch slices нельзя удерживать после следующей операции. Контрольные PSK
в тестах (нули/11...) намеренно публичны и не являются credentials.
