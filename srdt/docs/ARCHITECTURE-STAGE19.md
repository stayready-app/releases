# Архитектура SRDT — Stage 19

Текущая спецификация: [STAGE19.md](STAGE19.md). Окна приёмного резервирования:
[STAGE17.md](STAGE17.md). [Предыдущая архитектура](ARCHITECTURE-STAGE18.md) сохранена
полностью, включая исходные требования; утверждения о старых этапах не описывают текущий код.

## Рабочая цепочка

```text
Application message -> bounded Queue -> reserved receiver window
                    -> exact DATA transmission ledger -> wire congestion window
                    -> paced DATA / adaptive retry
                    -> authenticated secureudp session -> UDP socket
                    -> authenticated decode -> bounded Receiver -> retained message
```

Message ID/offset не зависят от физической упаковки. Повтор может иметь другие размеры;
новая AEAD-шифровка всегда получает новый криптографический counter. Отдельный DATA
PacketNumber идентифицирует физическую попытку (это НЕ AEAD-counter). Пакетный ACK
подтверждает конкретную попытку и её логический диапазон. Другие копии сохраняются
в учёте до собственного ACK или таймаута. Legacy-режим остаётся range-only.

Сервер владеет одним UDP socket и одним циклом событий; heap содержит не более одной
записи на сессию. Общий budget резервирует payload, bitmap и ограниченные метаданные.
Приёмные резервы выдаются до DATA. Собранный буфер переносится в очередь echo без копии.
Контроллер темпа использует фиксированное состояние; журнал физических DATA-передач
ограничен 128 записями и отдельным резервом 8192 байта на направление. Payload в нём
не копируется. Этот бюджет не расходует уже выданные приёмные разрешения.
Поиск ACK/вставка — O(1), сканирование не более 128 записей только при сроке expiry.
Журнал сохраняется до закрытия сессии, в том числе при простое после обмена.

ACK и разрешения не проходят через pacer DATA. Сигналы congestion принимаются только
из проверенного ACK конкретной отправки или локального timeout; чужой неаутентифицированный пакет не меняет
окно. При этом удаление/задержка пакетов противником может уменьшать скорость.

## Разделение реализации и планов

Реализован конечный message-based UDP echo-test, а не произвольное сетевое приложение.
`ExchangeBatch` удерживает предоставленный тестовый набор и историю результатов; это
не memory-bounded streaming API. UDP packet ограничен 1200 байт. Альтернативные carriers,
миграция, Xray/sing-box bridge, TUN-адаптер и эксперименты с IP-фрагментацией отсутствуют.

Общая архитектура допускает реальные TCP/TLS, WS, HTTP/2, QUIC носители. Для надёжного
носителя собственные retransmit/pacing/CC не должны бездумно дублировать нижний уровень.
Ротация независимых физических соединений и обнаружение протокола DPI относятся также
к уровню выше конкретного UDP encoder. Не обещана неразличимость от HTTP/QUIC.

Криптографический слой остаётся старым экспериментом X25519+лабораторный PSK/AES-GCM.
Нет индивидуального provisioning, безопасного постоянного identity/epoch lifecycle,
завершающего надёжного закрытия и реального долговременного возобновления после падения.
Сведения о реальных портах StayReady не угадываются: текущий проект независим от его кода.

## Проверки

См. [BUILD-REPORT.md](BUILD-REPORT.md) и [SECURITY.md](SECURITY.md). Для каждого этапа
поставляется полный архив, build/unit/race/vet, fault/regression tests и журнал результатов.

совместный запуск с Xray, WAN, DDoS или длительный soak test.
