# SRDT — Stage 18

Экспериментальный Go-проект передачи независимых сообщений поверх UDP.
**Лабораторный прототип. Не публиковать как VPN/proxy-сервис.**

## Изменения этого этапа

Поверх резервируемого приёмного окна Stage 17 добавлены независимое окно перегрузки
и ограничитель темпа DATA в обоих направлениях. Новые байты допускаются только при
наличии разрешения получателя **и** доступного окна отправителя. Повторные передачи
также проходят pacer; ACK и управляющие разрешения не блокируются окном DATA.

При таймауте контроллер уменьшает окно; новые уникальные ACK позволяют восстановить
его. Запас для burst ограничен, простаивающая сессия не накапливает безграничную пачку.
На быстрых каналах допустимая пачка учитывает гранулярность таймера, но ограничена
окном и абсолютным пределом. Дополнительное состояние фиксированное; нет новых
goroutine/таймеров на пакет или сессию.

Исправлено зависание короткого остатка сообщения при постоянной фильтрации его длины:
повторы циклически меняют разбиение даже для диапазона, уже меньшего RetryFragment.
Устранено дробление новых данных на крошечные фрагменты из-за остатка окна:
отправитель и планировщик ждут полного фрагмента либо настоящего хвоста сообщения.
Добавлена FIFO-модель узкого канала с ограниченной очередью и реальными UDP relay-тестами.

Это **экспериментальный контроллер по логическим диапазонам**, а не RFC-совместимый QUIC
или полное решение congestion control. Точный учёт физических копий в полёте ещё требует
пакетных подтверждений. Криптография и протокол начального обмена не менялись.

Подробности и ограничения: [docs/STAGE18.md](docs/STAGE18.md).
Проверки, реальные измерения, неудачные попытки: [docs/BUILD-REPORT.md](docs/BUILD-REPORT.md).
История предыдущих этапов сохранена отдельно.

## Компоненты

* `reliable`: фреймы, Sender/Queue/Receiver, владение буферами и общий Budget,
  точные и оконные разрешения, учёт диапазонов, RTT/RTO, экспериментальный congestion window и DATA pacing.
* `secureudp`: существующий экспериментальный X25519+PSK / AES-256-GCM слой.
  Криптографический handshake в Stage 18 не заменён.
* `netreliable`: один UDP listener / цикл событий, общий планировщик, лимиты сессий,
  реальные сетевые тесты, продолжительный echo-обмен.
* `emulator`, `testkit`: воспроизводимые данные, проверка, сетевые воздействия.
* `cmd/srdt-server`, `cmd/srdt-client`, `cmd/srdt-load`, `cmd/srdt-test`.

## Ограничения по умолчанию

| Ресурс сервера | Ограничение, не предвыделение |
|---|---:|
| Общий Budget учитываемых payload/bitmap/metadata | 64 МиБ |
| Суммарный RX+TX payload одной сессии | 64 КиБ |
| Незавершённые RX+TX сообщения одной сессии | 8 |
| Максимальный размер сообщения multi-сервера | 32 КиБ |
| Окно неподтверждённого ответа | 16 КиБ |
| Активные сессии | 1024 |
| Сессии с одного IP | 64 |
| Progress timeout | 15 с |

Budget НЕ является лимитом RSS. Runtime, maps, allocator overhead, криптографическое
состояние и сокеты требуют дополнительной памяти. Неиспользованные разрешения
подчиняются тем же лимитам и освобождаются при закрытии/таймауте сессии.
Новых goroutine/таймеров на сообщение или сессию не добавлено.

## Сборка и проверка

В архиве исходники и лабораторные бинарники Linux/Windows amd64. Использованный здесь
Go 1.23.2 уже не поддерживается. Получить новый compiler в этом окружении не удалось;
актуальный govulncheck не запускался. Для дальнейшего испытания вне лаборатории
обязательны поддерживаемая версия Go, повторные проверки и аудит криптографии.

```bash
go build ./...
go test -count=1 ./...
go test -race -count=1 ./...
go vet ./...
bash scripts/verify.sh
```

Для воспроизведения сетевых измерений на Linux после сборки `bin/`:

```bash
python3 scripts/integration.py --bulk
python3 scripts/integration.py --only active500
python3 scripts/integration.py --only active1000
python3 scripts/compare.py --baseline /path/to/extracted/srdt-stage17 --runs 3
python3 scripts/cli_smoke.py --baseline /path/to/extracted/srdt-stage17
```

Скрипты сравнения требуют отдельно собранный Stage 17 и Python 3. Не запускать
нагрузочные измерения параллельно друг другу. Генератор нагрузки — отдельный процесс;
его память нельзя выдавать за потребление сервера. Он намеренно хранит тестовую пачку.

## Локальный пример

Секрет ниже — переменная, а не готовый ключ. PSK в аргументах процесса допустим только
для лаборатории; не подставлять рабочие секреты, которые попадут в shell history.

```bash
GOMAXPROCS=2 GOMEMLIMIT=128MiB ./bin/srdt-server-linux-amd64 \
  --multi --listen 127.0.0.1:19443 \
  --psk "$SRDT_TEST_PSK" --metrics-file server-stats.json
```

Сервер печатает `SERVER_PUBLIC` и `LISTEN_ADDR`. Клиенту требуется именно этот
публичный ключ. При перезапуске текущего прототипа identity меняется.

```bash
./bin/srdt-client-linux-amd64 \
  --server 127.0.0.1:19443 --server-public "$SERVER_PUBLIC" \
  --psk "$SRDT_TEST_PSK" --batch 12 --bytes 4096 --timeout 30s
```

Для Windows-клиента и Ubuntu-сервера использовать адрес лабораторного/private
интерфейса Ubuntu, привязать сервер к нему и открыть UDP только между тестовыми
машинами. Не публиковать порт для всего Интернета. В PowerShell:

```powershell
.\bin\srdt-client-windows-amd64.exe `
  --server "${UbuntuTestIP}:19443" `
  --server-public $ServerPublic `
  --psk $SrdtTestPsk `
  --batch 12 --bytes 4096 --timeout 30s
```

Windows-бинарники кросс-компилированы, но здесь не запускались в Windows.
`GOMAXPROCS=2` не имитирует слабый CPU, а `GOMEMLIMIT` — мягкий лимит Go runtime,
не ограничение физической памяти процесса.

## Совместимость

Новый сервер принимает точные разрешения Stage 16 и оконные разрешения Stage 17.
Новый клиент по умолчанию требует оконный режим. Для старого Stage 16 сервера нужен
явный флаг `--legacy-credits` клиента/load-generator. Скрытого downgrade нет.
`--allow-legacy-data` сервера сохранён для ещё более старого DATA-first режима.
Другие существующие CLI-параметры не удалены. Stage 18 сохраняет wire-совместимость
со Stage 17: дополнительного флага между ними не требуется. `--no-congestion` добавлен
только для лабораторного A/B; для обычных тестов он не нужен.

## Не готово и не следует считать решённым

Нет полноценного packet-level congestion control с проверенной сетевой fairness.
Логический контроллер и pacing реализованы, но могут снижать скорость при выборочной
фильтрации/потерях. Не реализованы потоковое приложение вместо конечной пачки,
Xray/sing-box bridge, альтернативных carriers, миграции сессии или безопасной
долговременной ротации identity. HELLO всё ещё имеет фиксированную длину 81 байт;
его адресная фильтрация мешает установлению связи. ACK и legacy-управление также
имеют узнаваемые длины. Формат не маскируется под настоящий HTTP/QUIC.

Физические UDP-пакеты ограничены 1200 байт. Реальных испытаний на слабой VPS 2 ГБ,
с Xray, на Windows, в WAN/сетях операторов/ТСПУ и многодневного soak test нет.
Результаты loopback/искусственной задержки относятся к нашему echo-стенду, не к VPN.
